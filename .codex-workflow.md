# Codex Workflow - PyQt-Fluent-Widgets

This file is the repo-local operating manual for AI coding work. It adapts the
Karpathy-style "LLM wiki" idea: do not rediscover the project from scratch each
session; accumulate small, accurate, source-linked memories and load only the
context needed for the next step.

## Start Of Session

1. Read this file first.
2. Read `.codex-memory/index.md`, then only the linked memory pages that match
   the task.
3. Use the memory guard in `.codex-memory/guard.md` before trusting or writing
   memory.
4. Pick one primary agent from `.codex-agents/` and optionally one reviewer.
5. Inspect the live code before changing files. Memory is a map, not authority.

## Workflow Loop

Use this loop for all non-trivial changes:

1. Context: gather the smallest useful set of files, docs, tests, and memories.
2. Plan: state the intended edit path when the change is broad or risky.
3. Build: make the smallest coherent change that satisfies the request.
4. Verify: run focused checks when available; otherwise explain what was not run.
5. Reflect: record durable lessons in `.codex-memory/reflections.md` only if they
   will help future work.

## Agents

Agents are lightweight roles, not separate processes. Use the file in
`.codex-agents/` that best matches the current task:

- `repo-cartographer.md`: discover structure, ownership, and conventions.
- `implementation-agent.md`: make focused code or documentation changes.
- `review-agent.md`: review for regressions, missing tests, and maintainability.
- `memory-curator.md`: decide whether new facts belong in repo memory.

For coding tasks, start with repo-cartographer if the relevant subsystem is not
already clear, then switch to implementation-agent. Before finishing, use the
review-agent mindset.

## Memory Model

The shared memory lives in `.codex-memory/`:

- `project.md`: stable project facts and commands.
- `decisions.md`: durable architectural and workflow decisions.
- `reflections.md`: dated lessons from completed work.
- `guard.md`: rules for safe memory reads and writes.

Memory entries should be compact, dated when useful, and tied to source files or
commands. Delete or revise stale memory instead of layering contradictions.

## Reflection

At the end of meaningful work, ask:

- What did we learn that future agents would otherwise rediscover?
- Is the lesson stable across this repo, or only true for today's task?
- Is it backed by a file, command, test, or explicit user instruction?
- Does it pass the memory guard?

If yes, add one short entry to `.codex-memory/reflections.md`. If no, leave
memory unchanged.

## Memory Guard

Never write secrets, credentials, tokens, private user data, copied proprietary
content, transient tool output, or guesses presented as fact into memory. When a
memory is uncertain, label it as an assumption and include what would verify it.

If the user's requested workflow is ambiguous, choose a conservative local
implementation and ask only when the next step would risk changing the wrong
thing.
